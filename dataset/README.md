# dataset — 공통 데이터(내용) + 테스트 데이터 생성

- **담당:** 미정 (정해지면 이 줄과 `.github/CODEOWNERS`의 주석 처리된 줄을 수정)
- **요구사항 모듈:** M7 공통 데이터(내용), M9 테스트 도구 중 데이터 생성
- **요구사항 ID:** DAT-03, TST-01·02·03(정답), TST-04(리스트 원본)
- 저장소(스키마 적용 순서·버킷·초기화 스크립트)는 D 담당

C(검증)와 D(감시·롤백)가 일을 시작하려면 **과거 거래와 정답 라벨이 먼저 있어야** 합니다. 그래서 이 폴더가 1차의 선행 작업입니다.

## 핵심 원칙: 정답은 만들 때 같이 생긴다

- 생성기가 서류에 값을 찍는 순간 **그 값이 정답**입니다. 사람이 라벨링하지 않습니다.
- 기대 분류(`expected`)는 OCR 결과가 아니라 **정답 필드값**에 고정 규칙을 적용해 계산합니다. 시스템 출력으로 시스템을 채점하는 순환을 피하기 위해서입니다.
- 리스트를 새로 만들면 **그 리스트 버전의 기대 분류를 다시 계산**해 골든셋 버전을 하나 더 만듭니다 (DAT-03, TST-03).
- **시드 고정:** 같은 시드면 같은 서류·같은 라벨 (재현성).
- 실제 회사·개인 정보가 담긴 송장·B/L 이미지는 쓰지 않습니다.

## 폴더

| 폴더 | 내용 | 산출물 위치 |
|---|---|---|
| `spec/` | 필드 정의(`fields.md`), 정답 라벨 형식(`label.schema.json`), 골든셋 manifest 형식(`manifest.schema.json`) | git |
| `generator/` | 송장·B/L 템플릿 → 값 채우기 → PDF/PNG → 노이즈(기울기·흐림·저해상도·JPEG) + 라벨 JSON | `data/docs/`, `data/labels/` |
| `lists/` | 초기 리스트, 시연용 변형(정상 추가·대량 삭제·변조·손상) 원본. **서명은 B의 `signer/`** | git (원본만) |
| `golden/` | 리스트 버전별 `golden-<list>/manifest.json` (정답 목록, 이미지는 `data/`) | git |
| `seed/` | 과거 거래 적재: 합성 서류를 최초 번들로 A의 평시 경로에 넣어 거래·판정·번들 ID 저장 | DB, SeaweedFS |
| `tests/` | 같은 시드 → 같은 출력, 라벨이 스키마를 만족하는지 | — |

## 일정 (1차 기준, 데이터가 가장 먼저)

| 날짜 | 산출물 | 받는 쪽 |
|---|---|---|
| 11/11 | `spec/` 확정 (필드·라벨·manifest 형식) | 전원 — 이것이 데이터 계약 |
| 11/12 | 생성기 v1 + 서류 20건 + 라벨 | A (OCR 확인), C (mock 테스트) |
| 11/13 | 과거 거래 100건 적재 스크립트, `golden-list-v1` | C, D (`reset_demo.sh`) |
| 11/14 | 시연 리스트 v2(추가) + `golden-list-v2`, 변조·손상 리스트 원본 | B (서명), C (S2) |

규모: 과거 거래 **100건 이하**, 골든셋 **20~30건** (MTG-02에서 확정).

## 실행 (형태는 담당자가 확정)

```bash
python -m dataset.generator --seed 42 --count 100 --out data/
python -m dataset.seed --bundle B-1
pytest dataset/tests
```
