# TradeProof (AI-system-capstone)

외환·무역 심사 AI의 **OCR 모델 갱신을 안전하게 운영하는 체계**입니다.
모델 파일을 반입할 때 검증하고 → 과거 거래로 미리 돌려 보고(골든셋·Replay) → 게이트가 자동 배포 / 담당자 승인 / 차단을 정하고 → canary로 조금씩 반영하고 → 반영 후 감시하다가 이상하면 자동으로 되돌리고 → 과거 판정을 다시 재현합니다.
실행 환경은 은행 폐쇄망을 가정한 로컬 쿠버네티스(k3s)입니다.

- 요구사항·성공 기준: [docs/requirements.md](docs/requirements.md) (조원 「프로젝트 요구사항 최종」 기준)
- **모듈 간 연동 약속: [docs/interfaces.md](docs/interfaces.md)** ← 연동을 바꾸면 반드시 여기부터

## 구현 단계

**11/12 계획 변경([결정 0005](docs/decisions/0005-model-path-only.md)):** 모델(OCR) 갱신 경로만 구현합니다. 제재 리스트는 **고정된 한 버전**을 심사에 그대로 쓰고, 리스트 갱신(반입·Replay·반영·버전별 골든셋)은 하지 않습니다. 1차/2차 구분은 없앴고, **시스템을 끝까지 빠르게 구축하는 것**이 1순위입니다.

| 기간 | 범위 |
|---|---|
| ~ 11/22 (기능 동결) | 모델 갱신 경로 전체: 반입 → 검증 → 게이트 → canary → 감시·자동 롤백 → 재현 |
| 11/23 ~ 11/26 (최종 제출) | 리허설·보고서 |

**지금은 정상 모델 하나로 끝까지 가는 흐름(S4·S6)만 만듭니다.** 성능 저하·변조·손상 모델이 필요한 S1·S5는 시간이 남으면 추가합니다.

| 시나리오 | 내용 | 주 담당 | 상태 |
|---|---|---|---|
| S4 | 정상 개선 모델 → 골든셋·Replay 검증 → 게이트(자동 배포 또는 승인) → canary 10→50→100, 감시 지표가 기준을 넘으면 자동 롤백 | D (검증·게이트 C) | **지금** |
| S6 | 모델 갱신 후 과거 거래를 당시 번들(모델)로 재처리 → 기록된 판정과 일치 | C | **지금** |
| S1 | 변조·손상 **모델 파일** 반입 → 서명·해시 검증 실패로 등록 전 차단 | B | 시간이 남으면 |
| S5 | 성능 저하 모델 → 반입은 통과, 골든셋 기준 미달로 게이트 차단, canary 미실행 | C | 시간이 남으면 |

S2·S3(리스트)은 삭제했고 번호는 그대로 둡니다. 승인 요청·반려는 S4의 게이트 안에, 자동 복구는 S4 canary의 자동 롤백으로 남습니다. (시나리오 세부는 팀 확정 전 제안)

**지킬 설계:**
번들은 모델 + (고정) 리스트 묶음 / 거래마다 처리한 `bundle_id` 기록 / 옛 모델 파일 삭제 금지 / 검증 처리 API는 `bundle_id`를 받는 범용 형태 / 게이트 결과에 자동 배포·승인 요청·차단 3가지 자리 / 번들 교체는 Rollout + `BUNDLE_ID` 환경변수.

## 협업 규칙 (요약)

1. **자기 폴더만 고친다.** 다른 폴더가 필요하면 담당자에게 이슈/단톡방으로 요청.
2. **연동(API·데이터·코드 import·K8s)이 생기거나 바뀌면 즉시**
   ① `docs/interfaces.md`에 한 줄 추가 → ② 단톡방 공유 → ③ PR에 `contract-change` 라벨.
3. 브랜치는 `<모듈>/<주제>` (예: `d/compose-seaweedfs`, `data/generator-v1`), `main`에 직접 push 금지.
4. PR 제목은 `[A] …` `[B] …` `[C] …` `[D] …` `[DATA] …`, 리뷰 1명 + CI 통과 후 병합.
5. 필드 이름·코드값·상태값은 문자열로 쓰지 말고 `common/contracts.py`에서 가져온다.
6. 비밀값(.env), 생성 데이터(`data/`), `.venv`는 올리지 않는다.

## 빠른 실행 (개발용 docker compose)

```bash
cp .env.example .env              # 값은 개발용 그대로 써도 됨
docker compose up -d postgres minio minio-init
docker compose ps                 # postgres healthy, minio running 확인
```

모듈 서비스는 각 담당자가 Dockerfile을 완성하면 `docker-compose.yml`의 주석을 풀어 추가합니다.
시연 환경(k3s)은 D가 관리합니다. 팀원은 Dockerfile까지만 책임집니다.

## 실행 환경 공통 규약

Python 3.13, FastAPI, psycopg3, pytest. 의존성은 `==`로 버전 고정, 베이스 이미지 태그 고정.
모든 서비스는 `GET /healthz`(준비 상태, 실패 503), `GET /livez`, `GET /metrics`(이름 `tradeproof_<모듈>_<대상>`)를 가진다.
에러 응답은 `{"code","message","target_id"}`, 시간은 UTC ISO8601(`+00:00`), 로그는 한 줄 JSON + `X-Request-ID`, 행위자 헤더는 `X-Actor`.
감사 기록 기능은 범위에서 제외(11/9 결정) — 반입·승인·배포 이력은 각 모듈 테이블에 남긴다.
