# c_replay — 검증(골든셋·Replay·재현) + 게이트·승인

- **담당:** C 강민성
- **요구사항 모듈:** M2 릴리스 관리(게이트·승인·반영 요청), M3 검증
- **포트:** 8200
- **요구사항 ID:** REL-01~03, VAL-01~04

## 1차 (~11/17, 리스트 S1~S3)

- [ ] 골든셋 검증: 후보·운영 번들의 정확도·미탐을 나란히 + 차이 (VAL-01). 골든셋은 **후보 리스트 버전**의 것을 사용
- [ ] Replay: 과거 거래 전체를 후보 번들로 재처리, 건수 일치, 달라진 거래와 이전·후보 값 (VAL-02·03)
- [ ] 게이트: 자동 배포 / 승인 요청 / 차단 중 하나 + 판정 지표값 (REL-01·02). 리스트는 자동 배포 없음. 기준은 `contracts.py` 상수
- [ ] 승인·반려 API, 승인된 후보만 D에 배포 요청 (REL-03)
- [ ] `job/`: Replay Job 진입점. **K8s Job과 일반 프로세스 둘 다로 실행 가능**하게 (compose에는 Job이 없음)
- [ ] 배포할 번들 ID를 `deploy/`에 기록하는 방식 정리 (D와 협의)

## 2차 (S4~S6)

- [ ] 모델 변경 검증 (A의 OCR 코드 사용), 게이트 차단 (S5)
- [ ] 재현: 기록된 번들로 재처리, 기록과 전건 일치 (VAL-04)

## 제공하는 것 / 받는 것

| 제공 | 받는 쪽 | 받는 것 | 주는 쪽 |
|---|---|---|---|
| 게이트 결과·지표·영향 거래 | 운영 화면(A) | 판정·OCR 코드 (import) | A |
| 승인·반려 API | 운영 화면(A) | 거래·판정·원문 (읽기) | A |
| 배포 요청 `POST /deployments` | D | 골든셋·manifest | 데이터 |
| 번들 ID (`deploy/`) | D → A | 번들 구성·상태 전이 | B |
| | | Replay Job 시작 | B |

## 실행·테스트

```bash
pytest c_replay/tests
python -m c_replay.job --replay-id RP-... --index 0 --count 1   # 일반 프로세스 실행 예 (형태는 C가 확정)
```
